# go-png

又在终端里为个编码解码去开浏览器搜网页？别了，一行命令的事。

PNG 编码自己写（IHDR/IEND/IDAT 块、CRC、像素封装全手写），IDAT 用标准库 `compress/zlib` 压缩。

功能：

- 纯色背景 / 线性渐变背景
- 画实心矩形
- 用内置 5x7 像素字体绘制文字

```bash
# 纯色背景
go-png -out a.png -w 200 -h 100 -bg #202020

# 渐变背景
go-png -out b.png -w 200 -h 100 -grad #ff0000,#0000ff

# 画矩形
go-png -out c.png -w 200 -h 100 -bg #222 -rect 10,10,80,60,#00ff00

# 画文字
go-png -out d.png -w 200 -h 100 -bg #222 -text "Hi 1" -fg #ffffff -at 20,20
```

选项：

| 选项 | 说明 | 默认 |
|------|------|------|
| `-out` | 输出文件路径（必填） | 无 |
| `-w` | 宽度 | 200 |
| `-h` | 高度 | 100 |
| `-bg` | 背景色 `#rgb` 或 `#rrggbb` | `#202020` |
| `-grad` | 渐变两端色（逗号分隔） | 无 |
| `-rect` | 矩形 `x0,y0,x1,y1,color` | 无 |
| `-text` | 文字内容 | 无 |
| `-fg` | 文字颜色 | `#ffffff` |
| `-at` | 文字位置 `x,y` | `10,10` |

颜色支持 `#rrggbb`、`rrggbb`、三位简写 `#rgb`（`#f0a` = `#ff00aa`），大小写和首尾空格都能接受。

## 测试

```bash
go test ./...
```

30 个用例，覆盖像素读写、尺寸校验、填充与矩形裁剪、颜色解析（含各种非法输入）、渐变端点与回绕回归、文字绘制与字体覆盖、参数解析、写入错误传播、端到端产物校验、zlib 压缩效果。

关键的一点：PNG 产物是**交给标准库 `image/png` 解码后逐像素比对**的，而不是只检查文件里有没有 `IHDR` 字样——后者连 CRC 算错都发现不了。

## 几处已修的坑

- **白→黑渐变整片纯白**：`lerpRGB` 里写的是 `uint8(float64(a) + t*float64(b-a))`，`b-a` 是 **uint8 减法**，结束色比起始色暗时会回绕。白(255)→黑(0) 的 `b-a` 等于 `1`，于是整条渐变全程约等于 255。实测中点得到 `R=255`（应为 128）。改成先各自转 `float64` 再相减，顺带加了钳位和四舍五入。
- **渐变永远到不了结束色**：分母用的是 `W+H`，但 `x+y` 的最大值是 `(W-1)+(H-1)`，右下角始终差一截。改成 `W+H-2`，并特判 1×1 图避免除零得 NaN。
- **写失败静默成功**：`writeChunk` 没有返回值，所有 `w.Write` 的错误全被丢掉，`Save` 只返回 `Flush` 的结果；`defer f.Close()` 的错误也被吞了——而带缓冲的文件系统上，真正的写失败往往正是在 `Close` 才报出来。磁盘满或只读时会告诉你"已生成"。现在逐层返回错误，失败时删掉半截文件。
- **非法尺寸生成坏 PNG**：`-w 0` 会产出一个标准库直接拒绝解码（`non-positive dimension`）的文件；`-w 100000 -h 100000` 则会去分配 30GB。现在 `NewImage` 返回 error，并加了 8000 万像素上限。
- **小写字母全变成 `?`**：字体表只有大写键，`-text "hi"` 画出来是 `??`。现在查不到时先转大写再查。
- **常用符号缺失**：`,` `;` `_` `+` `=` `*` `/` `\` `()` `[]` `<>` `#` `%` `@` `&` `$` `"` `'` 原来都会回退成 `?`，现在补齐了字形。
- **`-at` 解析失败静默回退**：`-at abc` 会悄悄用 10,10，用户拿到一张位置不对的图却没有任何提示。现在明确报错；文字整体画到画布外时也会给出提示。
- **错误信息打到 stdout**：原来 9 处 `fmt.Println(err)` 全走标准输出，管道场景下会混进数据流。现在统一写 stderr。
- **CRC 计算多复制一份数据**：`crc32.ChecksumIEEE(append(typeBytes, data...))` 结果正确，但会为整个 IDAT 再拷一份。改用 `crc32.Update` 分两段累加，零拷贝。

## 其他说明

- 输出为 8 位真彩色（RGB）PNG，浏览器与系统图片查看器均可直接打开
- 新增 `Encode(io.Writer)`，可以直接编码到内存，不必先落盘再读回
- 新增 `TextWidth(s)`，画之前就能算出文字占多宽
- IDAT 走标准库 `compress/zlib` 压缩，纯色大图能压到原始体积的 1% 以下
